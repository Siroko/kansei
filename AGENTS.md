# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

## Where work happens

- Active development is the Rust engine in `rust/` (workspace: `kansei-core`, `kansei-wasm`, `kansei-native`); the TypeScript library in `src/` is the older port. Open PRs against `development`, not `main`.
- kansei.graphics is a Vercel production build of `main`: `pnpm bundle-examples` (Node 24.x, see `engines`), output `dist/`. The landing page is `site/` (copied to the dist root) and the curated list is `examples/index.html`; `development` reaches the site only when merged into `main`. The Rust examples and demos are served at `/examples/<name>/` from the `site-wasm` branch, which `.github/workflows/site-wasm.yml` builds on pushes to `main` (`scripts/build-wasm-examples.sh`, which says what it leaves out); the Vercel build only copies it in, so a page must load everything by relative URL (the build rewrites its `../pkg/` import). `fluid.kansei.graphics` (Vercel project `kansei-fluid`, root `rust/kansei-wasm/examples/fluid/`) builds nothing: its `vercel.json` proxies `kansei.graphics/examples/fluid/`.
- Two tiers of standalone crates, each with its own `[workspace]` and listed under `exclude` in `rust/Cargo.toml` (names are unique across both): `rust/kansei-wasm/examples/*` each teach one engine feature, and `rust/kansei-wasm/demos/*` are showcases (lake, motion-matching, voxel-gi-particles, fluid_clock, steering_text, joydivision) that may carry art-directed WGSL and their own logic, their READMEs naming what is demo-local. Build one with `wasm-pack build --target web --release` in its directory, serve that directory, and open `www/`. Their web plumbing (canvas sized by CSS box and device pixel ratio, resize, frame loop, query params, fetch) comes from `rust/kansei-wasm` (`Canvas`, `run`, `param`): don't copy it into an example. Examples and demos use kansei-core's public API only (`cargo test -p kansei-wasm` fails on an `include_str!` into kansei-core's files): what an example needs from a private shader becomes a public constant or stock material. Surfaces drawn through a `PostProcessingVolume` start from `Material::standard_lit` (scene lights and shadows, sky hemisphere, emission, instancing, velocity), `Material::emissive` and `Material::gradient_sky`; custom shaders compose `lights::LIGHTS_WGSL`, `shadows::SHADOW_MAP_WGSL` and `materials::GBUFFER_OUT_WGSL` instead of re-declaring those bindings.
- Textures ship as KTX2 (Basis Universal), transcoded per device by `loaders::ktx2`; encode with `rust/tools/ktx2` (needs `basisu`). See `docs/ktx2.md`. The transcoder crate is vendored and trimmed in `rust/vendor/basisu` (`PATCHES.md`): a new target needs its dispatch arm back.

## Verifying

- `cargo test -p kansei-core` validates every WGSL module with naga and checks each `#[repr(C)]` uniform struct against its WGSL size (see the `shaders_validate_*` tests); keep that pattern for new shaders. Chrome rejects some WGSL naga accepts (reserved words such as `patch` as names; `f(a < b, c > d)` read as a template list, so parenthesize the comparisons): load a new shader in the browser too.
- `rust/kansei-core/tests/*_gpu.rs` run shaders on a real adapter and read results back; they pass without running when no adapter exists.
- Headless browser checks: run `chrome-devtools-axi` with its own `CHROME_DEVTOOLS_AXI_SESSION` and `CHROME_DEVTOOLS_AXI_CHROME_ARGS="--enable-unsafe-webgpu --enable-gpu --ignore-gpu-blocklist"`, and serve examples on a port nobody else uses, with `Cache-Control: no-store` (Chrome otherwise keeps the old `pkg/` from `python3 -m http.server` across rebuilds).
- GPU cost in the browser: wgpu 24's WebGPU backend does not implement `queue.on_submitted_work_done`. Add `--disable-gpu-vsync --disable-frame-rate-limit` to the Chrome args and time the interval between frames. For a breakdown, `Renderer::set_profiling(true)` then `take_profile().report()`: every labelled pass's GPU time (`profiling::gpu_pass` on new passes) and the frame's CPU sections; add `--enable-webgpu-developer-features` for unquantized timestamps. Other sessions share this Mac's GPU, so separate runs differ by tens of percent: alternate A and B inside one page (the occlusion-culling example's `bench=1`). The profiler times a frame only while one of its 8 readbacks is free, so under load its timings arrive seconds late: after switching live, wait about 4 s before a profile window. On Apple GPUs consecutive passes overlap, so time a span across passes rather than each pass's own timestamps. Leave no animating WebGPU page open between captures (load `about:blank`).

## Sharp edges

- The TS engine imports some WGSL straight from `rust/kansei-core/src` with Vite `?raw` (`src/materials/shaders/SharedWGSL.ts`, under the Rust constant names; `assemble` in `ShaderUtils.ts` mirrors Rust's concat and `KANSEI_*` replace). Editing one of those files, or the bindings it declares, changes both engines: load the TS examples that include it too.
- `queue.write_buffer` lands before the next submit: several writes to one buffer inside a submit leave only the last one for every pass. Give per-dispatch parameters their own slots (or buffers).
- Each `queue.write_buffer` costs tens of microseconds in Chrome: upload a frame's data in one write, not one per dispatch or object (`culling::InstanceCulling` writes all its views once a frame, into one buffer its dispatches index).
- Depth is `[0, 1]` in both engines (`glam::Mat4::perspective_rh`; TS `Matrix4.perspective`/`ortho` use gl-matrix's `perspectiveZO`/`orthoZO`, never plain `mat4.perspective`), cleared to 1.0, so a depth of 1.0 means sky. Front faces are counter-clockwise and materials cull back faces by default.
- The GBuffer's four MRT targets fill WebGPU's default 32 bytes per sample (rgba8unorm counts 8), and wgpu 24's web backend cannot request more: another per-pixel output needs its own pass, as the velocity pass does.
- Shadow, reflection and velocity passes redraw each material through its own `vertex_main`, with the light or mirror as the camera (see `Material::get_depth_pipeline`). Vertex shaders must not read group 3. Mark `@builtin(position) @invariant` where a second pass depth-tests against the GBuffer.
- Apple GPUs drop hidden opaque fragments whatever the draw order, but not fragments that write `@builtin(frag_depth)` (shaded before any depth test) or may `discard` (spared only by what was drawn before them): a pile of impostors shades most of its layers. Draw the quad at the sphere's nearest point (no frag_depth), and give costly shading a depth prepass and an equal-depth pass, both `@builtin(position) @invariant` (`voxel-gi-particles`' spheres). Moving opaque walls after the impostors measured slower.
- Group 3 (shadows and lights) only grows by additive bindings; `renderers/shared_layouts.rs` lists them. It is fragment-only: compute passes read the lights and shadow maps through `shadows/compute_shadows.rs` (group 0 bindings 1 and 3-9, shared by the volumetric fog and voxel GI's injection).
- Voxel GI of meshes (`Renderer::enable_voxel_gi`, shown by `gi::VoxelGIEffect`) voxelizes only renderables with `Renderable::gi`, through their own `vertex_main`; varying albedo needs the material's `voxel_fragment_entry` (`gi::VOXEL_WRITE_WGSL`: group 3 bindings 100-102 in that pass). Static renderables are revoxelized only when transform, visibility or surface change: call `SceneVoxelGi::invalidate` after changing a texture. Behind thick walls with unlit outer faces the cones keep about 80% of the light (`tests/voxel_gi_scene_gpu.rs`); `rust/kansei-native/examples/gi_box_reference.rs` path-traces gi-box as the reference. Its distance field (`SceneVoxelGi::enable_sdf`, read with `gi::SDF_WGSL`) floods only the static seeds when they change and the dynamic ones every frame; on surfaces use `sdfSurfaceShadow`, not `sdfSoftShadow`, or a surface shadows itself at grazing angles. Its probes (`SceneVoxelGi::enable_probes`) trace that field and read the lit volume; `VoxelGIEffect::set_probes` swaps the per-pixel cones for them, and materials read them with `gi::PROBES_WGSL` (`kansei_gi_irradiance`).
- Voxel GI past a room is a clipmap round the camera (`Renderer::enable_voxel_clipmap`, shown by `gi::VoxelGIEffect::with_clipmap`): it revoxelizes only the slabs its windows move into, draws instanced renderables through cull views of its own (`InstanceCulling::with_gi_lod_range` picks the LOD they voxelize; cards keep their alpha test through `kansei_voxel_write_coverage`), and reads black until its sky is set (`SceneVoxelClipmap::use_sky_lighting`). Its probes (`enable_probes`) give materials sky visibility (`gi::CLIPMAP_PROBES_WGSL`) and the fog its ambient (`VolumetricFogEffect::set_clipmap_probes`); the `outdoor-gi` example uses them all.
- Ray tracing (`kansei_core::rt`): `Renderer::enable_rt_grid` keeps a grid of world triangles round the camera (or a fixed box) from the renderables with `Renderable::rt`, culled and cluster-cut for its box on the GPU; instanced ones need an `rt_placement` that does what their vertex stage does. Trace it from compute with `rt::RT_GRID_WGSL` (`RtGrid::bindings_wgsl`; the includer defines `kansei_rt_covered` for alpha tests) and give effects `SceneRtGrid::handle`, which follows its buffers when they grow. `RtReflectionsEffect` reflects only surfaces whose material returns `kansei_gbuffer_out_specular`: F0 lives in the GBuffer normal's alpha and roughness in the albedo's, so leave those alphas at 1 elsewhere.
- Instances culled on the CPU for the camera also drop out of shadow maps and reflections. Use `culling::InstanceCulling`, which culls per view on the GPU.
- Cluster LOD (`Renderable::clusters`): each view draws its own cut, but impostor bakes and point-light (cubemap) shadows draw the renderable's geometry, which must be the mesh its graph was built from.
- Skinned materials (`animation::SKINNING_WGSL`) skin in their own `vertex_main`, but the single directional shadow map (`enable_shadows`) draws casters with a shared depth shader: a skinned mesh casts its bind pose there, so use cascaded shadows.
- Never commit animation data, character meshes or anything derived from them (glTF exports, `.kmm` packs) unless their licence allows a public MIT repo: third-party sets such as Epic's GASP stay in a private folder, and the motion-matching demo (kept off the site; its `www/kimodo.html` plays the generated packs) loads packs from a local path (`rust/kansei-anim-bake/README.md`). Its world (course, lake, cannon, mill) is the pack-free `lake` demo's crate, which it depends on. Generated clips (`rust/kansei-anim-bake/genanim`, NVIDIA Kimodo in Docker on an NVIDIA PC) stay out of git too, and GASP is NoAI: no GASP pose, clip, render or the mannequin may go into a generator; they meet only at bake time. Music recordings never go in the repo or the site either (`.gitignore`, and `scripts/build-wasm-examples.sh` fails on audio): an example plays a file the viewer supplies, as `joydivision` does.
- `FluidMarchingCubes` draws voxel faces unless `set_use_classic(true)` (interpolated marching cubes). For a liquid's surface, `DensityFieldOptions::particle_radius` swaps the splatted density for a surface field (iso 1): spray stays droplet-sized and settled layers read flat. Walls, floors and moving colliders act on the fluid as `FluidSubstepPass`es run per substep (`update_batched_with`); the `lake` demo (`rust/kansei-wasm/demos/lake`) shows them. `FluidSimulationOptions::solver` picks SPH or Position Based Fluids (`simulations/fluid/pbf.rs`) on the same buffers, grid and substep passes. That grid is `simulations::grid::NeighbourGrid` (`FluidSimulation::grid`): other particle systems sort into one of their own, and passes that walk one bind its `params_buffer` with `NEIGHBOUR_GRID_WGSL`, not a copy. A fluid nobody sees or touches can rest: `FluidStepper::with_rest` (fixed steps at a `WorldScale`, over `FluidSleep` and `FluidSpeedProbe`), its state shown with `FluidSurfaceEffect::set_activity`, as the lake does; fill it at rest density with `PlanarContainerShape::lattice` or `fill_box` and `lattice_density`. The effect's surface goes into the scene as `FluidSurfaceEffect::surface_renderable`; step simulations with `pacing::FixedStep`. Fluid can be added at runtime: `FluidSimulation::with_capacity` reserves room, `emit`/`FluidNozzle` append into it (every pass runs on the live `particle_count`), `reset_particles` restores a fill; water squeezed between a collider and the container floor jitters and never sleeps, so keep colliders clear of the bed.
- Animation code (`animation/`, `collision/`) is clean-room: from papers and permissively licensed code, credited in the module docs. Never port Unreal Engine source (PoseSearch, AnimationWarping…) or GASP Blueprints; read what a clip needs from its tracks, not engine metadata.
